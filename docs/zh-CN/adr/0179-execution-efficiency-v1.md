# ADR 0179：Execution Efficiency V1（执行效率 V1）

**简体中文** · [English](../../en/adr/0179-execution-efficiency-v1.md)

- 状态：已接受
- 日期：2026-09-26
- 范围：Main Agent 回合中的建议式执行阶段与低信息探索提示

## 背景

Runtime Trace 显示，较长的仓库任务主要耗时在 Provider 请求，工具执行较快。现有调度器已经能并发运行同一模型响应中连续且安全的调用，但无法合并模型在不同响应中逐次发出的单个调用。改变工具调度或增加 Planner 会给依赖关系、Prompt Cache 连续性、权限和现有 Supervisor 边界带来风险。

## 决策

**效率反馈只提供建议，不拥有执行权。** 每回合的应用层控制器观察有界的 `ToolExecutionObservation` 事实和已完成调用的安全调度模式。它不会选择、合并、抑制、重排、重试或执行工具；不会改变 `max_steps`、推理强度、权限、沙箱、验证或 Supervisor 决策。Supervisor 仍是唯一的循环保护权威。

**只检测重复的低信息探索。** 候选轮次必须是一次新的、成功的 `ProgressKind.EVIDENCE` 调用，使用简单且可安全并行的仓库读取/搜索工具（`read_file`、单项 `read_files`、`grep_many`、`list_tree`、`glob` 或 `git_inspect`）。多文件 `read_files`、多查询 `grep_many`、错误、重复的 action/observation fingerprint、非证据结果、exclusive 工具和多调用批次都不计为单项轮次，并会打断 streak。连续两轮符合条件，或现有结构化计划的步骤全部完成时，本回合只触发一次有界的 `EXPLORE → ANALYZE` 检查点。提示模型综合现有证据、指出具体缺口，并将互相独立的后续读取合并，同时保留真实依赖步骤。该提示只是指导，不判断正确性，也不设置步数上限；新证据和有理由的后续探索仍可继续。

**证据批次由模型声明。** Runtime 不会凭空生成或合并调用。模型可以在一个 step 请求多个互相独立的读取/搜索；现有 scheduler 只并发执行其可执行工具能力确认安全的调用，保持结果顺序，并串行执行 exclusive、有副作用及交互控制调用。下一步依赖某项结果的工作必须等待该结果，并在后续模型 step 中执行。

**执行阶段通过有界 Context 提供提示。** 回合从 `EXPLORE` 开始。低信息检查点或现有计划完成进入 `ANALYZE`；分析检查点后出现新证据会回到 `EXPLORE`，但不重复提示。观察到工作区变化和验证时进入 `VERIFY`；验证成功后可进入 `FINALIZE`，所有终态路径都会记录完成阶段。阶段提示作为仅追加的 synthetic user context，只在阶段边界发送，不进入持久 Session history，也不追溯改写稳定 System Prefix。不会额外调用模型 Planner/Judge。

**Trace 只记录事实，不做决策。** 现有临时 Trace event 接收类型化阶段/原因、有界 streak/证据计数以及是否发出提示。它不接收 Prompt 正文、工具参数、结果正文、fingerprint 或密钥。策略完成决策后才把事件交给 Trace；Trace 继续作为只读可观测投影。

## 基准夹具

确定性的 repository-review 夹具在两组运行中都读取相同的五个审查文件，并返回相同的幂等性结论。碎片化基线使用五个单项证据批次后再发起最终请求（6 个模型请求、5 次工具调用、5 个批次、每批 1.00 个工具、60 个输出 token）。优化运行先单项读取两次，收到有界提示后将其余三次读取组成一个批次（4 个模型请求、5 次工具调用、3 个批次、每批 1.67 个工具、44 个输出 token）。两组夹具的缓存复用率均为 0.80。Provider 延迟由进程内模拟；耗时下降只代表夹具结果，不是线上 Provider 性能承诺。夹具会验证结论相同、证据覆盖完整、请求 Context 只追加、System 内容稳定以及持久历史不变。

## 后果

- 仓库探索可将碎片化读取往返变为模型声明的批次，同时保留现有安全流水线。
- 首次识别低信息模式时只追加一条有界 Context 消息；原始证据仍保留在会话投影中，后续证据不会被过滤。
- 验证和完成阶段是阶段边界，不是批处理触发器。
- 模型遵循提示时，Provider 延迟与输出 token 可能下降；不设固定下降目标，也不声称线上性能结果。
- Trace 仍仅供诊断。效率状态按回合创建且不持久化。

## 验证

确定性测试覆盖 singleton 检测、重复/错误/复合读取及多调用边界、提示后的新证据、工作区/验证阶段、exclusive 工具顺序、循环保护兼容性、Trace 脱敏、Prompt Cache 只追加结构、持久历史排除，以及有代表性的 repository-review 前后基准夹具。
